# 網址收藏庫

一個放在 GitHub Pages 的個人網址收藏網站。用 Google 帳號登入，資料存在你自己的 Firebase（Firestore），換裝置登入同一個帳號就能看到。整個網站只有一個 `index.html`，不需要安裝或建置。

## 功能

- **分區：** 最外層先分成不同分區（例如工作、學習、生活），每個分區有自己的連結和分類。
- **多個分類：** 一個連結可以同時屬於多個分類，分類選單可以用文字篩選。
- **全部搜尋：** 最外層的搜尋框會同時搜尋所有分區的連結、備註、分類與分區名稱。
- **圖片：** 每個連結、每個分區可以各放一張小圖片，沒有圖片時顯示首字母。
- **隱藏：** 連結可以設成「隱藏」，隱藏的連結不會出現在最外層搜尋，也不會被分享。
- **分享：** 可以分享整個分區或單一連結。
  - 任何有連結的人：不用登入就能看。
  - 指定的 Google 帳號：在欄位裡輸入帳號，會跳出最接近的建議，一格一格新增或刪除，對方要用該帳號登入。
  - 分享內容會自動同步，對方開啟的是唯讀頁面。
- **深色與淺色主題**，手機和電腦都能使用。

## 設定步驟

你需要一個 GitHub 帳號和一個 Google 帳號，全部在網頁上操作。

### 1. 建立 Firebase 專案
1. 到 https://console.firebase.google.com ，用 Google 帳號登入，按「建立專案」。
2. 名稱隨意，Google Analytics 可以不開。

### 2. 取得網頁設定並貼進 `index.html`
1. 專案首頁按「</>」（網頁）新增應用程式，取個暱稱。不用勾選 Firebase Hosting。
2. 畫面會顯示 `firebaseConfig`，把 `apiKey`、`authDomain`、`projectId`、`appId` 四個值，貼到 `index.html` 上方同名的位置。
3. 這組設定會公開在網頁原始碼裡，這是正常的，它不是密碼。真正保護資料的是第 4 步的規則。

### 3. 開啟 Google 登入
1. 左側「建構」>「Authentication」>「開始使用」。
2. 「登入方式」選 Google，啟用並儲存。
3. 切到「設定」>「已授權的網域」，新增你的 GitHub Pages 網域，例如 `你的帳號.github.io`（只填網域，不含路徑）。沒加的話登入會失敗。

### 4. 建立資料庫並貼上規則（最重要）
1. 左側「建構」>「Firestore Database」>「建立資料庫」，選離你近的地區，用「正式版模式」。
2. 到「規則」分頁，把 `firestore.rules.example` 的內容整份貼上，**把 `YOUR_EMAIL@gmail.com` 換成你自己的 Gmail**，按「發布」。
3. 沒做這一步，或規則寫錯，資料可能被別人讀寫，或你自己反而打不開。

### 5. 部署到 GitHub Pages
1. 把 `index.html` 放進 repository 的根目錄。
2. Settings > Pages，Source 選 `Deploy from a branch`，Branch 選 `main`，資料夾選 `/ (root)`，儲存。
3. 等一兩分鐘，用 `https://你的帳號.github.io/repository名稱/` 開啟，按「用 Google 帳號登入」。

### 6.（建議）限制 API key 的使用範圍
到 Google Cloud 主控台的「API 和服務」>「憑證」，找到 Firebase 自動建立的瀏覽器 key，「應用程式限制」選「網站」，加入 `https://你的帳號.github.io/*` 與 `https://專案ID.firebaseapp.com/*`。「API 限制」不要亂改，否則登入可能壞掉。

## 使用分享

- 分區卡片和連結列都有「分享」按鈕。
- 最外層的「分享網址」區塊會列出所有分享，可以複製連結、修改對象、停止分享。
- 對方開啟的連結長這樣：`https://你的帳號.github.io/repository名稱/#share=亂碼`。
- 只有你開著網頁時才會同步分享內容，編輯後請讓頁面保持開啟幾秒。
- **指定帳號的名單：** 網站沒辦法查某個 Google 帳號是否真的存在，所以名單是「登入過這個網站的帳號」。輸入不在名單裡的帳號，會提示「目前不存在此帳號」。要加入還沒登入過的人，請他開分享視窗裡的「邀請連結」（網址結尾是 `#join`），登入一次就會登記。
- 停止分享，或刪除被分享的分區或連結，對方就立刻看不到。

## 資料與隱私

- 資料存在你的 Firebase 專案裡，不在 GitHub，也不在瀏覽器。
- 你的原始資料只有你的 Google 帳號（規則裡填的 Gmail）可以讀寫。
- 分享是另外複製的一份獨立副本，不會開放你的原始資料，標成「隱藏」的連結不會被複製。
- 公開連結一旦外流，知道網址的人都看得到。想停止，按「停止分享」。
- 指定帳號的名單，能打開那份分享的人，技術上也讀得到名單裡的電子郵件。
- 登入過這個網站的帳號（包含開過分享連結並登入的人）會在你的 `accounts` 集合留下電子郵件，只有你讀得到。
- 圖片縮成最長邊 192 像素，以小型資料存在 Firestore，不使用 Firebase Storage。
- 刪除沒有復原功能，重要的連結建議另外備份。

## 額度與限制

- 每顯示一張圖片，載入頁面時就讀取一次 Firestore。別人開啟分享也會消耗你的讀取額度。圖片或分享很多時請留意用量，免費額度請以 Firebase 官方說明為準。
- 一個分區最多顯示 1000 個連結，指定帳號每份分享最多 50 個。

## 檔案說明

| 檔案 | 用途 |
| --- | --- |
| `index.html` | 整個網站，唯一需要部署的檔案 |
| `firestore.rules.example` | Firestore 規則範本，貼到 Firebase 前請換成你的 Gmail |
| `README.md` | 本說明 |
| `CHANGELOG.md` | 更新日誌 |

> 請不要把填了你真實 Gmail 的 `firestore.rules` 放進公開的 repository。範本檔使用佔位字串。

## 疑難排解

- **登入失敗，顯示網域未授權：** 到 Authentication >「設定」>「已授權的網域」新增 `你的帳號.github.io`。
- **登入後出現權限錯誤：** 規則裡的 Gmail 打錯，或登入的不是那個帳號。
- **畫面一直顯示載入中：** 檔案預覽視窗跑不了這個頁面，請在瀏覽器用 GitHub Pages 網址開。
- **分享按鈕按了失敗：** 規則還沒更新成新版，「分享網址」區塊也會提示。
- **登入出現 `api-key-not-valid`：** `apiKey` 複製錯誤，請從 Firebase「專案設定」重新複製。
